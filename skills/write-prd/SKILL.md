# Write a PRD (showcase)

## When to use

A feature or site scope needs a document engineers and designers can act on without ten follow-ups.

## Inputs

- Problem and user (who hurts, what they’re trying to do)
- One primary success metric
- Rough effort envelope
- Explicit non-goals

## Sections to produce

1. **Problem statement** — 3–5 sentences
2. **Hypothesis** — If we do X, Y improves because Z
3. **Success metrics** — primary (+ optional secondary)
4. **Target user / scenario**
5. **Requirements** — MUST / SHOULD / COULD, testable
6. **User flows** — happy path + empty/error
7. **Non-goals**
8. **Open questions**
9. **Risks**

## Quality bar

- Every MUST requirement is testable.
- No invented external facts — mark unknowns.
- Short enough to approve in one Gate 1 read for this demo.
